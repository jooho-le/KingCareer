# KingCareer Gemini 모델 한도 조사 및 선정

2026-09-13 현재 로컬에 설정된 API 키의 Google Cloud 프로젝트를 대상으로 조사했다. 다른 계정이나 배포 환경에 동일한 한도가 적용된다고 가정하지 않는다. 모델·키·과금 설정은 변경하지 않았다.

## 선정 결과

- 기본 모델 추천: **`gemini-3.5-flash-lite`**.
- 예비 모델 추천: **`gemini-3.1-flash-lite`**.
- 두 모델 모두 현재 프로젝트의 무료 한도가 **15 RPM / 250,000 입력 TPM / 500 RPD**다. 현재 `gemini-3.8-flash`의 **5 RPM / 250,000 입력 TPM / 20 RPD**보다 일일 호출 한도가 25배 크다.
- 실제 앱 어댑터로 힌트·상황 생성·평가·회고를 각각 한 번씩 호출해 두 모델 모두 4/4 성공했다. 근거 ID와 추천 키 검증도 통과했다.
- 3.5 Flash-Lite의 평균 응답 시간은 약 1.5초, 3.1 Flash-Lite는 약 1.8초였다. 표본이 작고 순차 검사였으므로 장기 안정성이나 일반적인 성능 우위를 보장하는 수치가 아니다.

## 조사 방법과 증거

1. Gemini `models.list`를 페이지 끝까지 조회해 55개 모델의 메타데이터를 수집했다. 생성 호출은 하지 않는 읽기 작업이다.
2. 이미 로그인된 gcloud 계정으로 API 키의 프로젝트를 확인하고 Service Usage API의 `consumerQuotaMetrics.list?view=FULL`을 조회했다. 86개 지표를 받았다. 키·OAuth 토큰·프로젝트 식별자는 보고서에 포함하지 않았다.
3. 무료 생성·임베딩 관련 모델별 할당량 252개 항목을 추출했다. 여기에는 현재 모델 목록 밖의 구형·내부 차원도 포함되므로 252개 모델이 사용 가능하다는 뜻은 아니다. `effectiveLimit`를 사용했으며, 할당량을 알아내려고 호출을 반복해 소진하지 않았다.
4. 한도와 용도가 적합한 후보에 동일한 가상 과제를 보냈다. 환경 파일을 바꾸지 않고 검사 프로세스에서만 모델명을 교체했다.

- [무료 할당량 항목 CSV](data/gemini-free-quota-buckets-2026-09-13.csv)

CSV의 `mapping=exact`는 API 모델 ID와 할당량 차원이 직접 일치한다. `family-inferred`는 미리보기·IT 등 접미사가 다른 모델을 같은 계열로 대응한 추정이며 별도 한도로 합산하면 안 된다. `unresolved`는 모델 이름만으로 할당량을 확정할 수 없는 항목이다. 55개 중 직접 대응 16개, 계열 대응 21개, 미확정 18개다. 미확정 항목은 latest 별칭과 Live·음악·영상·특수 모델 등이 중심이며 빈칸을 0이나 무제한으로 취급하지 않았다.

명시된 할당량 항목에서 숫자 필드가 생략된 경우 protobuf 기본값 0으로 읽었다. `-1`은 해당 지표의 무제한 값이며, 다른 지표·과금·접근 권한까지 무제한이라는 뜻이 아니다. 기본 버킷 값을 확인되지 않은 모델에 임의 적용하지 않았다.

## 텍스트 생성 모델 무료 한도

단위: RPM=분당 요청, 입력 TPM=분당 입력 토큰, RPD=일일 요청. **남은 사용량이 아니라 설정된 한도**다.

| 모델 | RPM | 입력 TPM | RPD | 판단 |
| --- | ---: | ---: | ---: | --- |
| Gemini 3.5 Flash-Lite | 15 | 250,000 | 500 | 기본 추천, 실제 4/4 성공 |
| Gemini 3.1 Flash-Lite | 15 | 250,000 | 500 | 예비 추천, 실제 4/4 성공 |
| Gemini 3.8 Flash | 5 | 250,000 | 20 | 앞선 QA에서 일일 한도 초과 확인 |
| Gemini 3.7 Flash | 5 | 250,000 | 20 | 일일 한도 확대 효과 없음 |
| Gemini 3.6 Flash | 5 | 250,000 | 20 | 일일 한도 확대 효과 없음 |
| Gemini 3.5 Flash | 5 | 250,000 | 20 | 일일 한도 확대 효과 없음 |
| Gemini 2.5 Flash | 5 | 250,000 | 20 | 일일 한도 확대 효과 없음 |
| Gemini 2.5 Flash-Lite | 10 | 250,000 | 20 | 생성 요청 404, 현재 후보에서 제외 |
| Gemini 2.5 Pro | 0 | 0 | 0 | 현재 프로젝트 무료 생성 할당량 없음 |
| Gemini 3 Flash Preview* | 5 | 250,000 | 20 | 계열 대응값, 고정 안정 버전 우선 |
| Gemini 3.1 Flash-Lite Preview* | 15 | 250,000 | 500 | 안정 버전과 별도 예산으로 보지 않음 |
| Gemini 3.1 Pro Preview / Customtools* | 0 | 0 | 0 | 계열 대응값, 무료 후보 제외 |
| Gemma 4 26B A4B IT* | 30 | 16,000 | 14,400 | 현재 JSON 어댑터 검증 실패 |
| Gemma 4 31B IT* | 30 | 16,000 | 14,400 | 현재 어댑터에서 30초 읽기 시간 초과 |
| Gemini Flash / Flash-Lite / Pro latest | 미확정 | 미확정 | 미확정 | 별칭의 독립 한도를 가정하지 않음 |

별표 항목은 API ID와 할당량의 모델 차원 이름이 달라 계열로 대응했다. Gemma는 같은 Google API로 호출 가능한 별도 모델 계열이며 Gemini와 동일한 응답 특성을 보장하지 않는다. 14,400회라는 RPD만 보고 선정하면 낮은 입력 TPM이나 출력 형식 문제를 놓칠 수 있다.

위 Gemini 텍스트 모델의 메타데이터상 입력 상한은 1,048,576 토큰, 출력 상한은 65,536 토큰이다. Gemma 두 모델은 입력 262,144, 출력 32,768 토큰이다. 이 문맥 길이 상한과 분당 처리량은 다른 값이다. 현재 앱은 요청별 출력 상한을 4,096 토큰으로 설정한다.

## 실제 후보 비교

기존 `GeminiProvider`의 시스템 지시, JSON 스키마, Pydantic 검사, 30초 대기 조건을 그대로 사용했다. 학생 데이터 대신 로그인 복구 설계라는 가상 과제를 사용했다. 테스트 입력에는 '아직 친구에게 시험하지 않고 계획만 세웠다'는 사실을 넣어, 계획을 이미 달성한 성과로 바꾸는지 확인했다.

| 모델 | 힌트 | 상황 생성 | 평가 | 회고 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 3.5 Flash-Lite | 1.40초 성공 | 1.55초 성공 | 1.40초 성공 | 1.59초 성공 | JSON·근거 ID·추천 키 검증 성공 |
| 3.1 Flash-Lite | 1.93초 성공 | 1.65초 성공 | 1.58초 성공 | 1.82초 성공 | JSON·근거 ID·추천 키 검증 성공 |
| 2.5 Flash-Lite | 0.51초, 404 | 중단 | 중단 | 중단 | 모델 목록·할당량 존재가 실제 생성 가능을 보장하지 않음 |
| Gemma 4 26B A4B IT | 1.54초, JSON 검증 실패 | 미실행 | 미실행 | 미실행 | HTTP 200·STOP이었으나 앱 스키마에 맞는 JSON 아님 |
| Gemma 4 31B IT | 30.29초, ReadTimeout | 미실행 | 미실행 | 미실행 | 한 번의 실패로 모델 전체 품질을 단정하지 않음 |

2.5 Flash-Lite의 404가 종료·접근 권한·현재 API 지원 중 어느 이유인지는 이번 응답만으로 확정하지 않았다. 공식 종료 일정에는 당시 종료일이 발표되지 않았으므로 '종료된 모델'이라고 단정하지 않는다.

수동 내용 검토:

- 두 Flash-Lite 모두 제공된 `record1`과 허용된 추천 키를 사용했다. 검사한 평가·회고에서 실제 사용자 시험을 완료했다고 만들어내지는 않았다.
- 3.5는 짧고 기록 중심이었다. 다만 '시험해본 계획', '반성(reflection)'처럼 어색하거나 학생 화면에 부적절한 표현이 있었고 내부 ID를 문장에 노출했다.
- 3.1은 힌트의 다음 행동이 구체적이고 친근했다. 반면 상황 응답에서 자료에 없는 데이터베이스 연결 원인을 일반화했고, 회고에서 결정의 어려움과 진로 불확실성 사이의 인과관계를 추정했다.
- 따라서 '모든 품질 문제가 해결됐다'는 판정은 아니다. 기본 모델은 3.5로 추천하되, 학생 문체·근거 범위 지시를 보완하고 다른 네 직업·긴 기록·모호한 답변도 적용 전에 추가 검증하는 것이 좋다.

## 나머지 모델 처리

이미지, TTS·전사, 실시간 음성, 음악·영상, 임베딩, 로봇·컴퓨터 사용·심층 조사 전용 모델은 55개 CSV에 포함했다. 현재 KingCareer는 텍스트 기반 코치·상황 응답·피드백·회고가 목적이므로 기본 LLM 후보에서 제외했다. 과금이나 한도를 확인하기 위해 유료 전용 모델에 생성 요청을 보내지는 않았다.

실시간 모델에 일반 `generateContent` RPM을 대입하지 않았다. 영상·실시간 세션 등은 별도 호출 방식과 지표가 필요하다. 최신 별칭도 변경될 수 있으므로 확정 모델 ID를 권장한다.

## 적용안

1. 기본 모델 `gemini-3.5-flash-lite`, 예비 모델 `gemini-3.1-flash-lite`를 선정한다. 이번 작업에서는 실제 설정을 변경하지 않았다.
2. 모든 학생이 공유하는 분당·일일 호출량을 관리한다. 한 학생의 중복 요청 방지와 프로젝트 전체 호출량 제한을 별도로 둔다.
3. 503은 제한적으로 지연 재시도하고, 분당 제한은 대기한다. 일일 한도 초과는 같은 모델 재시도를 멈추고 사용자에게 구분해 안내한다.
4. 예비 모델 전환도 해당 모델의 실제 한도 안에서 수행한다. 모델별 한도를 단순 합산해 항상 1,000회가 보장된다고 안내하지 않는다.
5. 과거 '아직 평가하지 않음'을 '미연결'로 표시하는 문제와 포괄적 오류 메시지도 함께 수정해야 한다.

## 공식 자료

- [Gemini 요금표](https://ai.google.dev/gemini-api/docs/pricing): 무료 제공 여부와 유료 단가. 실제 프로젝트의 호출 한도와는 별개다.
- [Gemini 한도 안내](https://ai.google.dev/gemini-api/docs/rate-limits): 프로젝트 기준 RPM·TPM·RPD, 태평양 시간 자정 초기화, 용량 변동 가능성.
- [모델 종료 일정](https://ai.google.dev/gemini-api/docs/deprecations): 구버전의 운영 가능성 확인.
- [Service Usage 할당량 조회 API](https://docs.cloud.google.com/service-usage/docs/reference/rest/v1beta1/services.consumerQuotaMetrics/list): 실제 프로젝트 할당량을 가져온 읽기 API.

프로젝트 한도는 시점과 계정 상태에 따라 달라질 수 있다. 이 표는 2026-09-13 조회 시점의 스냅샷이다.
