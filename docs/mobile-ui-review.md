# 모바일 UI 집중 리뷰 — 2026-09-13

## 1차 모바일 개편 반영

후속 요청으로 760px 이하에 전용 레이아웃을 적용했습니다. 아래 초기 리뷰는 변경 전 기록입니다.

- 일반 화면: 홈·직무체험·미니 프로젝트·포트폴리오 하단 메뉴. 기존 이동 함수를 사용하며 작업실·체험 안에서는 숨깁니다.
- 작업실: 설명·크랩 도움·과제가 작업 영역을 채우고 ‘그림으로’로 복귀합니다. 그림 편집기는 제거하지 않아 초안과 편집 상태를 유지합니다. 390×844에서 설명 패널이 약 297px에서 623px로 확대됐습니다.
- 체험: 조사 자료는 닫을 수 있는 비모달 하단 패널로 표시합니다. 상태·도구 영역을 줄이고 판단 중에는 3D 높이를 줄여 선택과 결과를 가깝게 배치합니다. 화면 설정·2D 대체 조작은 유지합니다.
- 목록·기록: 직업 카드의 이미지·문구 간격, 포트폴리오 소개, 프로필 헤더를 모바일용으로 조정했습니다. 크랩과 브랜드 색상은 유지합니다.
- PC·태블릿: 하단 메뉴와 모바일 전환 표현은 숨기며 기존 사이드바·캔버스/우측 패널 배치를 유지합니다. 768px와 1440px의 나란한 배치, 844×390 가로 화면의 접근성을 검사했습니다.

화면·체험·이동 관련 Playwright 10개와 실제 로컬 API 검사 5개가 통과했습니다. 새 `mobile-layout.spec.ts`는 모바일에서 입력 후 그림↔설명을 전환하고 저장을 거쳐 이동하는 흐름과 PC 배치 복원을 확인합니다. 실제 API 검사는 임시 계정으로 초안·그림 저장, 도움말, 수정 이력·제출·포트폴리오 복원과 이전 초안 호환을 확인하고 계정을 삭제했습니다. AI 응답은 대체했으며 실제 모델 호출 검사는 아닙니다. 최종 타입 검사·Vite 빌드도 성공했고 기존 큰 청크 경고는 남아 있습니다. 실제 기기의 가상 키보드·Safari·터치 성능은 별도 확인이 필요합니다.

## 초기 리뷰

현재 학생 앱을 Chrome 모바일 에뮬레이션으로 실행했습니다. 별도 FastAPI·SQLite와 가상 계정을 사용했으며 운영 학생 기록은 변경하지 않았습니다. AI는 template 모드입니다. 이번 작업은 진단이며 제품 UI는 수정하지 않았습니다.

## 확인 범위

- 홈, 직업 목록, 진단·답변 확인·결과, 체험 안내·3D 현장·조치 결과·수료, 프로젝트, 포트폴리오, 진로 기록, 프로필, 설정: 14개 상태.
- 390×844와 320×844에서 총 28개 레이아웃 측정. 412×915 기본 캡처도 보존.
- 390×844로 새 작업실을 열어 그림 전체 보기, 내 설명, 크랩 도움, 메뉴 열기·닫기를 직접 조작.
- 측정한 화면에서 문서 가로 넘침과 JavaScript 실행 오류는 관찰되지 않음.
- 실제 휴대폰, iOS Safari, 가상 키보드, 핀치 제스처, 저사양 GPU 성능은 아직 검사하지 않음. 체험 진행 상태 일부는 실제 API로 준비했으므로 모든 단계를 터치로 완주한 검사는 아님.

## 작업 순서 제안

1. 모바일 공통 화면 규칙: 상단 높이, 주 내비게이션, 터치 크기, safe-area.
2. 미니 프로젝트: 화면을 나눠 차지하는 패널 구조 개선. 자동 저장·뒤로가기 보존.
3. 직무체험: 현장→자료→선택→결과를 모바일에서 가까이 연결.
4. 목록·포트폴리오·프로필: 콘텐츠 우선순위와 카드 밀도 조정.
5. 실기기 확인: 키보드가 입력·제출을 가리지 않는지, 화면 회전·주소창 변화, 3D 터치와 발열·성능.

단순히 글자와 캐릭터를 줄이는 방향은 피합니다. 정보량을 조절하되 학생이 보는 재미와 직업별 개성은 유지합니다. 전용 모바일 레이아웃을 적용할 때에도 데스크톱 사이드바와 기존 저장 계약은 유지하는 방향입니다.
