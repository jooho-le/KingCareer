## 피드백에서 수정까지

아래 순서는 대화에서 다룬 문제의 흐름입니다. 각 행이 별도의 하루나 하나의 커밋을 뜻하지는 않습니다. 과거 캡처에는 이후 제거한 기능도 남아 있습니다.

| 사용자 관점에서 발견한 문제 | 수정 방향과 결정 | 확인 자료 |
| --- | --- | --- |
| 학생 서비스인데 기존 이름·교사 기능·체험판 느낌이 남음 | KingCareer 학생 중심으로 정리하고 크랩·단색 브랜드 요소 적용 | [디자인 개편](design-refresh.md), [IA](front-ia.md) |
| 소개에서 직무체험으로 이동하면 정리되지 않은 화면이 보임 | 소개→탐색→가입·체험 진입 경로 점검 | [사용 흐름](student-usability.md), 캡처의 `current-review` |
| 직업 지도·포트폴리오의 역할이 불명확함 | 진로 기록은 프로필에 모으고 포트폴리오는 실제 결과물 중심으로 정리 | [회고 설계](career-review.md), [흐름·저장 개선](review-improvements.md) |
| 설명이 많고 처음 무엇을 해야 할지 알기 어려움 | 화면 속 실제 버튼을 가리키는 도움말 오버레이, 다시 안 보기·설정에서 다시 보기 | [브라우저 검증](ui-validation.md), `ui-audit` 캡처 |
| 그림을 그리는데 페이지가 함께 움직이고 작업 공간이 좁음 | 캔버스와 페이지 스크롤 분리, 도구·패널 배치 조정, 모바일 접기 | [작업실 검증](ui-validation.md), `sidebar-review` 캡처 |
| 과제 패널 글씨·여백·버튼이 복잡함 | 과제·내 설명·크랩 도움 정리, 저장·제출 상태와 관심도 확인 | `ui-audit`, `writing-guide` 캡처와 검사 로그 |
| 미성년 학생에게 너무 단순하고 시선을 끌지 못함 | 주황·보라·파랑과 크랩 표현 강화, 핵심 행동은 유지 | `vibrant-home`, `vibrant-lobbies`, `vibrant-portfolio` 캡처 |
| 미니 프로젝트만 다른 내비게이션을 사용함 | 다른 화면과 공통 사이드바 사용, 모바일 메뉴·키보드 접근 확인 | `sidebar-review`, `sidebar-spacing` 캡처 |
| 직무체험 상단 안내가 너무 크고 실제 조치가 잘 드러나지 않음 | 현재 업무와 현장·선택·결과의 배치 조정, 다섯 직업·여러 화면 크기 검사 | [체험 설계](activity-design.md), `simulation-layout` 캡처 |
| 포트폴리오 팝업에서 결과물을 확인하기 어려움 | 설계도 우선 배치, 설명·회고·AI 피드백 분리, 닫기·다운로드 접근 개선 | `portfolio-preview`, `hand-flow/submitted-portfolio.png` |
| 프로필과 하단 계정 영역이 답답함 | 계정·설정 정리, 하단 여백 및 작은 화면 확인 | `profile-review`, `sidebar-spacing` 캡처 |
| 미니 프로젝트의 글쓰기 단계보다 그림 자체에 가이드가 필요함 | 여러 가이드 시안을 검토한 뒤 손그림 흐름도를 기준으로 통일 | [재설계 기록](mini-project-redesign.md), `project-learning`, `drawing-guide`, `hand-flow` |
| 초안과 완성 예시의 품질·구도가 달라 혼란스러움 | 네모·화살표·메모의 일관된 손그림 구성, 기존 초안과 수정 이력 보존 | [손그림 검증](ui-validation.md), `hand-flow` 캡처 |
| 빈칸 찾기가 불필요함 | 빈칸 찾기 기능 제거 요청 반영. 과거 카드·빈칸 화면은 이력으로만 공개 | [현재 웹 화면](web-wireframes.md), 이전 캡처와 구분 |
| AI가 연결됐다 안 됐다 함 | 로컬·운영 앱과 공급자 응답을 나눠 검사하고 오류 주입으로 원인 분리 | [AI 재검증](ai-qa-2026-09-13.md) |
| 무료 한도와 모델 선택 근거가 필요함 | 프로젝트 할당량 조회, 후보 모델 실제 호출 비교 후 Flash-Lite 선택 | [모델 선정](gemini-model-selection-2026-09-13.md) |
| 설정만 바뀌고 운영 반영이 안 될 수 있음 | 환경설정 변경→빌드·백엔드 검사→커밋·푸시→Vercel 배포→공개 API 검사 | [배포 후 QA](qa/flash-lite-rollout.md) |

## 검사를 어떻게 나눴나

| 검사 | 확인한 것 | 이 검사만으로 알 수 없는 것 |
| --- | --- | --- |
| 화면·브라우저 검사 | 모바일 넘침, 스크롤, 도움말 위치, 키보드 접근, 버튼·탭·다운로드 | 실제 학생의 학습 효과, 모든 보조공학 환경 |
| 실제 로컬 API 검사 | 임시 계정으로 초안·그림 저장, 새로고침 복원, 제출·수정 이력·삭제 | 모의 AI를 사용한 경우 실제 모델 품질 |
| 백엔드 회귀 검사 | 계정 분리, 중복 요청, 처리 중 삭제·수정, 실패 시 입력 보존 | 운영 환경의 지연·동시 사용자 수용량 |
| 공급자 직접 호출 | 실제 HTTP 상태, JSON 형식, 지연, 사용량 제한 | 사용자 화면의 모든 상태 전이 |
| 운영 앱 검사 | 실제 도움말·평가·회고 응답과 저장 보존, 임시 계정 삭제 | 장기간 무장애와 부하 상황 |

과거 단계별 통과 수는 서로 겹치는 검사가 있으므로 합산하지 않습니다. 실패한 로그도 보존하며, 최신 통과 여부는 해당 단계의 설명과 후속 로그를 함께 읽어야 합니다.

## 남아 있는 한계

Flash-Lite 배포 후 실제 AI 응답은 확인했지만, 오류 종류를 같은 연결 실패로 보여주는 처리, 기능별 공용 잠금, 평가 전 `not_connected` 표시 문제까지 이 모델 교체로 해결된 것은 아닙니다. 상세 내용은 AI 재검증 문서에 남겼습니다. 빌드의 큰 청크 경고도 남아 있습니다.

캡처는 개발·검사용 화면입니다. 중간 시안은 현재 제품 기능을 보증하지 않으며, 모바일 캡처는 Chrome 에뮬레이션으로 실제 Android 기기 검사를 대신하지 않습니다. 대화에 첨부됐지만 로컬 파일로 남아 있지 않은 사용자 원본 스크린샷은 이 저장소에 포함되지 않았습니다.
