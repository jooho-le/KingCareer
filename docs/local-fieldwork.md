# KingCareer 다섯 직무 현장 · 로컬 개발 범위

로컬 PC에서 실행하는 웹 화면과 Python 서버입니다. 다섯 직업 모두를 3D 현장 체험 → 수료 카드 → 설계 프로젝트 → 포트폴리오로 연결합니다. 전북에서 찾기 화면·메뉴·API는 제거했습니다. 소개 페이지의 해당 구역은 기존 배치를 살린 직무 현장 목록으로 바꿨습니다. 테스트 작성·실행은 사용자에게 맡깁니다.

## 실행

저장소 루트에서 두 터미널을 사용합니다. 처음 설치할 때의 가상환경 생성 방법은 [README](../README.md)를 참고합니다.

```powershell
# 첫 번째 터미널
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```powershell
# 두 번째 터미널
npm.cmd install
npm.cmd run dev
```

| 화면 | 로컬 링크 |
| --- | --- |
| 홈 | [KingCareer](http://127.0.0.1:5173/app/#home) |
| 스마트팜 현장 체험 | [온실로 출근하기](http://127.0.0.1:5173/app/#simulation?career=farmer) |
| 개선 설계 프로젝트 | [설계 작업실](http://127.0.0.1:5173/app/#projects?career=farmer) |
| 수료 카드·배지·결과물 | [나의 포트폴리오](http://127.0.0.1:5173/app/#portfolio) |
| API 문서 | [FastAPI](http://127.0.0.1:8000/docs) |

서버 시작 시 `002_project_scene.sql`이 기존 DB에 배치도 컬럼을 추가합니다. 계정과 이전 기록을 초기화하지 않습니다. SQLite와 체크포인트는 기존 `backend/storage`에 저장하며 uvicorn은 한 worker로 실행합니다. `localhost`와 `127.0.0.1`은 쿠키가 다르므로 위 주소로 통일합니다.

`003_simulation_variants.sql`은 기존 텍스트 세션을 `classic`, 현장 세션을 `fieldwork`로 분리합니다. 기존 기록을 삭제하거나 자동 완료하지 않습니다. 목록에서는 새 현장 체험을 바로 시작하며, 저장해 둔 이전 세션 URL로는 기존 체험을 이어갑니다. 새로고침과 서버 재시작 후에는 서버의 마지막 저장 단계부터 이어집니다.

## 체험과 결과물

3D 모델·재질·조명·카메라와 화질 선택의 후속 개선은 [3D 품질 문서](scene-quality.md)에 정리했습니다. 다섯 직업 공통 렌더링을 개선하고 자동차 모델과 일부 공통 가구를 CC0 GLB로 교체했습니다.

출근 → 6개 대상 조사 → 가설 선택 → 조치·이유 선택 → 재확인 방법 선택 → 인계 내용 선택 → 회고·관심도 → 수료 카드 순서입니다. 직업별 필수 자료 두 곳을 포함한 세 곳 이상을 조사한 뒤 가설을 고릅니다. 스마트팜의 필수 자료는 센서와 교대 일지입니다. 모든 필수 체험 응답과 회고는 객관식이며 글자 수 제한을 채울 필요가 없습니다. 코치에게 보내는 자유 질문만 선택적으로 작성합니다. 결과물을 만드는 미니 프로젝트의 설명은 기존 작성 방식을 유지합니다.

조치 후에는 환기창·팬·바람, 급수 물방울·탱크 수위, 담당자 모형이 선택에 따라 달라집니다. 2D 목록 모드에도 같은 조치 결과 카드와 전후 수치가 표시됩니다. 화면의 움직임은 서버 결과의 재현이며 움직임 줄이기 설정에서도 최종 상태는 보입니다.

처음 조사할 때만 가상 시간 3분을 사용합니다. 자동 환기 복구, 추가 급수, 담당자 점검은 서로 다른 시간·자원·후속 온도와 엔딩을 만듭니다. 모든 수치와 조작은 KingCareer가 만든 교육용 가상 상황이며 실제 농업 처방이 아닙니다. 게임 시간·자원은 경험지도 점수가 아닙니다.

3D는 [Greenhouse.tsx](../src/fieldwork/Greenhouse.tsx)의 Three.js 기본 도형으로 만든 온실입니다. 재배대·환경 센서·환기 제어기·급수 탱크·교대 일지·기상 관측기를 배치했습니다. 외부 GLB나 GPU 서버는 필요하지 않습니다. 회전·확대·조사 클릭을 지원하고, 아래 2D 목록으로도 같은 서버 행동을 수행합니다. 시스템의 움직임 줄이기 설정에서는 장식 움직임을 끕니다.

직무체험은 한 교대의 판단·인계를 경험하고 수료 카드를 받는 흐름입니다. 미니 프로젝트는 발견한 문제를 배치도와 개선 제안으로 제작해 포트폴리오를 만드는 흐름입니다.

## 직업별 현장과 프로젝트

| 직업 | 필수 조사 자료 | 조치에 따른 장면·결과 | 프로젝트 |
| --- | --- | --- | --- |
| 앱 개발자 | 오류 로그·배포 기록 | 이전 버전 복구, 서버 증설, 동료 설정 수정 → 화면·서버·실패율 변화 | 로그인 복구 설계 노트 |
| 간호사 | 인계 메모·호출 기록 | 통로 준비, 알림만 끄기, 팀 지원 요청 → 카트 이동·호출등·동료 등장 | 안심 교대를 위한 인계 보드 |
| 스마트팜 전문가 | 환경 센서·교대 일지 | 환기, 급수, 담당자 요청 → 창문·물방울·온도 변화 | 온실 개선 배치도 |
| 자동차 엔지니어 | 진동 기록·정비 이력 | 승인 점검, 전원 확인, 동료 재검토 → 휠·진단 화면·동료 등장 | 진동 문제 점검 흐름도 |
| 식품 연구원 | 배치 기록·측정 결과 | 혼합 시간 통제, 여러 조건 변경, 반복 측정 → 믹서·시료·측정 화면 변화 | 시료 비교 실험 설계서 |

네 직업의 내용은 [workplaces.json](../backend/data/workplaces.json), 진행 규칙은 [workplaces.py](../backend/workplaces.py), 3D 장면은 [WorkplaceScene.tsx](../src/fieldwork/WorkplaceScene.tsx)에 있습니다. 원인·조치·지표는 프로젝트가 작성한 가상 교육 콘텐츠입니다. 간호 체험은 환경 준비·소통·인계를 다루며 임상 판단이나 투약을 실행하지 않습니다. 3D 외부 에셋을 새로 받은 것이 아니라 Three.js 도형으로 제작했습니다.

각 프로젝트의 기본 도안은 직접 수정할 수 있는 네 단계 흐름도로 제공하며, 스마트팜은 기존 온실 도안을 사용합니다. 다섯 직업 모두 도형과 설명을 제출하면 해당 직업의 포트폴리오에 저장합니다.

## 기록 근거와 배지

| 기록 | 경험지도 반영 | 배지 기준 |
| --- | --- | --- |
| 대상 조사 | 열람 이벤트만 저장, 이해 목표에 가산하지 않음 | 서로 다른 네 곳 이상: 현장 탐색가 |
| 자료 비교 | `scenario_0` 기록 존재 | 비교와 조치 이유 작성: 근거를 잇는 사람 |
| 조치와 이유 | `scenario_1` 기록 존재 | 위 조건과 함께 계산 |
| 결과 확인 | `scenario_2` 기록 존재 | 결과 확인과 인계 작성: 다음 교대의 동료 |
| 회고·완료 | 회고와 완료 목표 충족 | 수료 카드 생성 |
| 배치도와 세 설명 제출 | 기존 프로젝트 목표 충족 | 개선 설계자 |

기준은 [fieldwork.py](../backend/fieldwork.py)에 있습니다. 작성·제출의 존재를 확인하며 정확성이나 직무 능력을 검증하지 않습니다. 배지에는 `criteriaVersion`과 `evidenceSources`가 저장됩니다. 수료 카드는 완료 활동 ID에서 파생하고 본인 활동만 조회합니다. 같은 완료·제출 요청으로 카드나 경험 목표를 중복 가산하지 않습니다.

수료 카드에는 기존 크랩 PNG 원본, 직업 그림, 닉네임, 완료일, 결과 요약과 획득 배지를 조합합니다. 새 직업별 복장 이미지를 AI로 생성한 상태는 아닙니다. SVG 다운로드는 크랩 PNG를 포함합니다. 원본 이미지의 브랜드 글자는 유지합니다.

## 프로젝트 저장

- 변경 후 1.5초 뒤 서버에 저장합니다. 완료 문구는 서버 응답 뒤 표시합니다. 저장 중 추가 입력은 다음 저장으로 이어집니다.
- 배치도와 텍스트는 같은 버전으로 저장합니다. 수정 이력 복원은 새 버전을 만듭니다. 이전 제출물은 변경하지 않습니다.
- 충돌 시 입력을 유지합니다. 작업 JSON 백업 또는 서버 기록 다시 읽기를 선택할 수 있습니다.
- 도형·화살표·텍스트 등 최대 250개, 직렬화한 배치도 500KB까지 저장합니다. 이미지·외부 링크·임베드는 제외합니다.
- 포트폴리오에서 제출 당시의 배치도를 다시 보고 SVG와 전체 결과물 JSON을 받습니다. 기존 전체 활동 텍스트 내보내기도 유지합니다.
- 작업 백업과 배치도 SVG는 화면의 현재 입력이며, 제출 결과물 JSON은 서버의 해당 수정본입니다.

Excalidraw는 작업실을 열 때 불러옵니다. `scripts/prepare-excalidraw.mjs`가 설치·개발·빌드 전에 폰트를 로컬로 복사합니다. 생성 폴더 `public/excalidraw-assets`는 Git에서 제외합니다.

`공개 배치도 도형 42개 가져오기`는 공식 Excalidraw Libraries의 Arqtangeles 배치도 묶음(MIT)을 로컬 파일에서 가져옵니다. 열린 라이브러리에서 도형을 눌러 배치합니다. `받아둔 라이브러리 파일 열기`는 2MB 이하의 `.excalidrawlib`를 가져오며, 삽입한 도형은 프로젝트에 저장됩니다. 라이브러리 목록 자체는 현재 편집기 세션에서 사용하고 다시 열 때 가져오기 버튼으로 복원합니다. PNG와 SVG 그림 다운로드를 모두 제공합니다. 이 라이브러리는 2D 도형이며 3D 모델이 아닙니다. [출처와 이용 조건](../public/libraries/README.md).

## Gemini 선택 연결

키 없이 체험·프로젝트·수료 기능을 사용할 수 있습니다. 기본값은 `template`입니다. 기존 `backend/.env`에서 아래 항목을 설정하고 Python 서버를 다시 시작합니다. 기존 `.env`를 예제 파일로 덮어쓰지 않습니다.

```dotenv
KINGCAREER_AI_MODE=ai
KINGCAREER_AI_PROVIDER=gemini
KINGCAREER_AI_MODEL=gemini-3.8-flash
KINGCAREER_AI_KEY=본인의_Gemini_API_키
```

모델 ID는 본인의 AI Studio 프로젝트에서 사용 가능한 텍스트 모델로 바꿉니다. 무료 사용 가능 여부와 한도는 해당 프로젝트 설정에 따릅니다. 코드가 유료 모델이나 다른 공급자로 자동 전환하지 않습니다.

다섯 현장 체험의 Gemini는 질문 설명과 별도로 요청한 프로젝트 텍스트 피드백을 맡습니다. 모델이 시간·자원·완료·배지를 결정하지 않습니다. 그림 속 글자와 설명만 전송하므로 시각적 배치를 검증했다고 표시하지 않습니다. 현장 체험의 `coachMode`는 서버 설정을 따라 기존 체험에서도 새로 불러온 뒤 질문할 수 있습니다. 이전 텍스트 체험의 AI 모드는 해당 세션 생성 때 정한 설정을 유지합니다.

키는 Python 서버에만 둡니다. 요청에는 계정·학교·프로필을 포함하지 않고 현재 가상 상황과 입력을 보냅니다. 개발용 가상 입력으로 사용합니다. 모델 다운로드와 H200이 필요하지 않습니다. API 오류·한도 초과·응답 형식 오류는 입력과 기존 상태를 보존하며 재시도할 수 있습니다. 제출과 AI 호출은 분리되어 피드백 실패로 제출물이 사라지지 않습니다.

구현: [inference.py](../backend/inference.py), API 계약: [Gemini generateContent](https://ai.google.dev/api/generate-content). 실제 키를 사용한 호출은 이번 작업에서 수행하지 않았습니다.

## 사용자 확인 항목

테스트를 작성하거나 실행하지 않았습니다. 타입 검사·프론트 빌드·Python 문법 확인은 기능 테스트와 구분합니다.

1. 3D 클릭과 2D 목록이 같은 조사 기록을 만드는지, 회전·확대·모바일·움직임 줄이기가 동작하는지.
2. 조사 → 비교 → 세 조치별 결과 → 재확인 → 인계 → 회고 → 수료 → 프로젝트 → 포트폴리오.
3. 반복 조사·요청 재전송·같은 수정본 제출에서 중복 차감·활동·배지가 없는지.
4. 계정 간 세션·수료 카드·초안·피드백·다운로드가 분리되는지.
5. 새로고침·Python 재시작 후 상태와 기록 복원, 서버 중단·두 탭 충돌 시 입력 보존과 재시도.
6. 자동 저장 중 추가 입력·제출·페이지 이동, 이전 수정본 복원, 저장 완료 표시 시점.
7. 수료 SVG, 배치도 SVG, 제출 JSON과 서버 기록의 일치.
8. Gemini 미연결 표시, 정상 응답과 429·오류 재시도, 제출 성공과 피드백 성공의 구분.
9. 다섯 직업별 도안·저장·수료 카드, 이전 텍스트 세션 URL 이어하기, 전북 메뉴 제거와 이전 `#region` 홈 이동, 소개 페이지 큐브·스크롤 유지.

기존 `tests/app.spec.ts`의 직무체험 세 번 선택 방식은 다섯 직업의 현장 조사 → 객관식 판단 → 조치 → 확인 → 인계 → 회고 단계로 갱신해야 합니다. 지역 탐색 기대값은 제거하고, 네 직업 프로젝트 제출에 도형 요소 조건을 추가해야 합니다. 이전 경로·저장소 기대값은 [기존 테스트 변경 안내](manual-review.md)를 참고합니다.

배포·네이티브 앱·AR·자유 이동형 월드·실시간 이미지 생성·3D 크랩 리깅은 이번 로컬 범위에 포함하지 않았습니다.
