# 미니 프로젝트 손그림 기준

2026-09-13. 사용자 확인: **손그림 흐름도가 기준이다.** 도안·완성 예시·최종 결과물은 같은 표현과 구도를 사용한다.

## 이번에 적용한 범위

- 다섯 직업의 새 프로젝트에 네모 네 개, 이어지는 화살표, 추가 확인이 필요한 가지선, 그림 속 메모를 준비한다. 간호사는 ‘호출 확인 → 환경 준비 → 팀 지원 → 다음 교대’를 사용한다. 직업마다 질문과 메모 내용은 다르다.
- Excalidraw의 손그림 선과 한글을 지원하는 Excalifont 기본 글꼴, 주황·보라·파랑 채움색을 사용한다. 도형과 글은 컨테이너로 묶고 화살표는 실제 연결 정보를 가진다.
- 도안과 완성 예시는 같은 함수에서 같은 도형 크기·위치·색·선을 생성한다. 예시는 메모만 채워서 보여준다. 학생의 그림과 메모는 제출 당시 요소 그대로 SVG·PNG·포트폴리오에 남긴다.
- 새 프로젝트에는 손그림 도안을 준비한다. 기존 그림은 변경하지 않는다. 전체 보기 버튼은 현재 그림의 위치만 맞추고 도안을 반복 추가하지 않는다. 새 손그림을 선택하면 현재 초안을 먼저 저장하고 수정 이력을 보존한 뒤 새 도안을 별도 수정본으로 저장한다.
- 제공 도안과 미완성 메모는 제출 완료로 처리하지 않는다. 초안 저장·관심도·설명·명시적 제출의 기존 흐름을 유지한다. AI 코치는 저장된 글과 도형·연결 정보에 대해 힌트를 주며 최종 그림을 다른 형태로 다시 생성하지 않는다.
- 이전에 저장된 `scene.studio` v2 대화형 초안은 호환 화면으로 유지한다. 해당 기록의 저장·체크 API도 유지한다. 파일 메뉴에서 손그림으로 전환할 수 있고, 기존 내용은 수정 이력에 보존된다.

아래는 이 확인 전에 논의한 재설계의 이력이다. 대화형 로그인 화면을 신규 기본으로 삼는 제안은 위 손그림 기준으로 변경했다.

## 이전 안에서 확인한 문제

- `project-templates.ts`는 다섯 직업 모두 1040×650 구도를 만들고 텍스트 빈칸 세 개를 넣는다. 개발자의 화면과 이동 경로, 자동차의 점검 표시 등이 처음부터 배치돼 있어 학생의 설계 선택이 작다.
- 기존 프로젝트 자료에 있던 개발자의 지원 요청·반복 실패 경로, 자동차의 재시험·인계, 연구원의 반복 측정 기록이 새 그림에서 충분히 드러나지 않는다. 화면에는 여전히 모든 프로젝트에 20–30분을 표시한다.
- `drawing-readiness.ts`와 `project_readiness.py`는 예약 빈칸이 없는지, 기본 문구와 다른 글이나 사용자 요소가 있는지를 확인한다. 실제 요구사항을 만족했는지 검사하지 않는다. 설명 세 개와 관심도를 입력해 제출하면 곧바로 완료 안내와 배지를 보여준다. 빈칸을 채우는 것만으로 자동 제출되는 것은 아니다.
- ‘그림 가이드 넣기’는 이미 도안이 있을 때 실제로는 해당 도안으로 이동한다. 안내가 상단 버튼·상태 문구·그림·과제 패널에 반복된다. 라이브러리 가져오기와 기본 편집기 라이브러리 사용도 나뉘어 있다. 동일 버튼의 중복 렌더링 자체는 확정하지 않았다.
- 고정된 큰 도안을 가용 공간에 자동 맞춤하고, 기존 그림 옆에 새 도안을 추가한다. 도안이 늘어날수록 전체 보기에서 내용이 작아진다. 텍스트와 도형이 대부분 분리되어 있고 화살표에 연결 대상 정보가 없어 조작 중 구도가 무너지기 쉽다.

## 서비스에서 맡을 역할

직무체험에서 겪은 문제를 가지고 학생이 한 가지 결과물을 설계·수정하고, 그 결과를 확인하는 작업실로 만든다. 시작 자료에는 충분한 현장 맥락과 편집 재료가 있어야 한다. 학생이 결정할 핵심 영역은 미완성 상태여야 한다.

도움을 그림 안에 넣는다는 뜻은 문제 지점의 표시, 일부 구성요소의 자리, 선택한 요소의 짧은 예시, 연결할 대상을 그림에서 발견하게 하는 것이다. 별도 단계 카드나 독립된 문장 빈칸 폼은 다시 만들지 않는다.

## 기준 프로젝트: 로그인 복구 화면

범위는 ‘로그인 실패 후 사용자가 다음 행동을 찾도록 만들기’ 하나로 제한한다. 결과물은 복구 화면을 포함한 화면 2–3개와 경로다. 전체 앱 개발이나 실제 인증 서버 구현은 요구하지 않는다.

**처음 보이는 작업물**

문제가 있는 기존 로그인 화면, 한두 개의 가상 사용자 문의, 편집할 오류 화면의 기본 틀을 제공한다. 기존 화면은 참고용으로 고정한다. 학생 작업에는 오류 안내 자리와 필요한 UI 구성요소가 있지만 문구·배치·경로의 해결책까지 정해 놓지 않는다.

**학생이 실제로 바꾸는 것**

- 사용자가 이해할 오류 안내를 화면에 놓고 수정한다.
- 재시도 버튼과 도움 요청 경로를 선택해 배치한다.
- 재시도했을 때 어느 화면으로 가는지 연결한다. 이전 입력을 유지할지도 정한다.
- 계속 실패하는 경우에도 빠져나갈 길이 있는지 살펴본다.

이 항목은 화면 밖의 단계 목록으로 만들지 않는다. 선택한 버튼의 속성·연결, 그림 안의 미완성 표시, 작업물 미리보기에서 자연스럽게 다룬다.

**결과를 확인하는 방법**

학생이 ‘작동 확인’을 열고 ‘연결이 돌아온 경우’와 ‘계속 실패하는 경우’에서 자기 버튼을 눌러 본다. 경로가 없으면 실제로 그 지점에서 멈추고 수정할 대상으로 돌아갈 수 있다. 확인 후 고칠지, 현재 결과를 제출할지 학생이 선택한다. 제출 전에는 자신이 바꾼 내용과 결과물 미리보기를 확인한다.

이 미리보기에는 의미가 정의된 버튼과 연결 정보가 필요하다. 일반 그림의 모양만 보고 동작을 추정하지 않는다. Excalidraw의 도형·글·연결에 프로젝트용 식별자와 행동 정보를 연결하고, 서버도 같은 정보로 검증한다.

## 작업실의 화면 배치

- 기존 공통 사이드바는 유지한다.
- 프로젝트 상단에는 제목, 자동 저장 상태, 주 행동 하나를 둔다. 작성 중에는 ‘작동 확인’, 검토 화면에는 ‘포트폴리오에 제출’이 주 행동이 된다. 저장 실패 시 같은 위치에 재시도를 표시한다.
- 중앙에는 한 작업물을 크게 표시한다. 초기 초안을 반복해서 추가하는 버튼은 없앤다. 참고 자료와 작업물의 경계를 분명히 한다.
- 편집 도구는 한 곳에서 제공한다. 직업용 구성요소는 기존 편집 도구와 함께 정리하고 별도 도구 바를 겹쳐 만들지 않는다.
- 옆 패널은 현재 선택한 요소의 속성·연결 또는 필요한 도움을 보여준다. 같은 안내를 상단·그림·패널에 반복하지 않는다.
- 예시와 크랩 도움은 하나의 참고 진입점 아래에서 선택한 부분에 맞춰 제공한다. 전체 완성 답안을 항상 앞에 노출하지 않는다.
- 내보내기·백업·수정 이력은 한 파일 메뉴에 모은다.

공간 기준은 고정 작업물과 구역 확대다. 넓은 화면에서는 작업물과 참고를 함께 보고, 좁은 화면에서는 작업 구역 하나를 읽을 수 있는 크기로 보여준다. 전체 그림을 작게 줄이는 것을 모바일 대응의 끝으로 삼지 않는다. 작업 중 줌·위치는 유지하고 ‘작업 전체 보기’로 돌아올 수 있다. 초기 가용 면적과 크기 변경 후 위치를 실제 브라우저에서 확인한다.

## 완료와 피드백

작성됨, 확인해 봄, 제출됨을 구분한다. 몇 글자 썼는지나 도형 개수로 직무 능력을 인정하지 않는다.

개발자 프로젝트의 구조 검사는 안내·버튼·이동 대상의 존재, 끊어진 연결, 예외 경로 등을 대상으로 한다. 사용자가 두 상황을 확인한 기록도 남긴다. 검사되지 않은 작업을 확인했다고 표시하지 않는다. 학생은 미완성 상태도 초안으로 저장할 수 있다.

AI는 선택한 요소의 문구나 설계 이유에 대한 힌트와 피드백을 준다. 결과물 전체를 자동 완성하거나, 저장 성공을 곧 학습 성공으로 표현하지 않는다. 학생이 확인하고 제출한 결과에 배지를 연결하며, 배지는 활동 완료를 뜻하고 직업 역량 인증을 뜻하지 않는다.

## 다섯 직업의 적정 결과물

| 직업 | 한 프로젝트의 결과물 | 학생이 결정할 핵심 | 결과 확인 |
| --- | --- | --- | --- |
| 개발자 | 로그인 복구 화면과 경로 | 안내·버튼 배치, 재시도·도움 요청 연결 | 정상 복구와 반복 실패 상황에서 눌러 보기 |
| 간호사 | 가상 병동의 인계 보드 | 필요한 준비 정보·담당자·미확인 항목의 배치 | 다음 교대자가 남은 일을 찾을 수 있는지 |
| 스마트팜 | 한 구역의 환경 점검 배치도 | 센서 위치·환기 확인 위치·점검 동선 | 선택한 구역을 빠뜨리지 않는지, 전후에 볼 기록 |
| 자동차 | 특정 진동 문제의 점검·재시험 설계도 | 점검 대상·동일 시험 조건·전후 비교 기록 | 조건을 맞춰 비교 가능한지, 남은 확인 사항 |
| 식품 연구 | 두 시료의 비교 실험 설계도 | 고정 조건·바꿀 변수·반복 측정 기록 | 여러 조건을 동시에 바꾸지 않았는지, 비교할 기록 |

다섯 직업에 같은 세 칸을 복제하지 않는다. 예상 시간은 실제 수행량을 구성한 뒤 확인하며, 모든 과제에 동일 시간을 일괄 표시하지 않는다.

## 구현 순서와 보존

1. 개발자 프로젝트에서 초안의 정보량, 실제 편집, 연결 미리보기, 검토·제출의 기준을 먼저 확정한다.
2. 공통 편집 도구·저장·줌·접근성을 정리한다. 배경은 고정하고 이동 가능한 구성요소의 도형·라벨·연결은 함께 움직이게 한다.
3. 다른 직업은 결과물과 확인 방법에 맞춰 각각 설계한다.
4. 기존 초안·제출물은 자동 변환하거나 지우지 않는다. 새 작업용 구조에는 버전을 부여하고 기존 그림은 저장한 내용 그대로 열 수 있게 한다. 새 도안을 기존 그림 옆에 무조건 덧붙이지 않는다.

구현 검사는 도형이 늘어나도 읽을 수 있는지, 실제 이동·연결이 유지되는지, 초안만 보고 할 일을 찾을 수 있는지, 연결되지 않은 결과물을 갑자기 완성으로 안내하지 않는지, 저장 실패·재접속에 작업이 유지되는지를 포함한다. 학생 대상 사용성 확인은 별도로 필요하며 코드 검사 통과로 대신하지 않는다.
