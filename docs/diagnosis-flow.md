# 관심·경험 진단 연결

6개 객관식 카드 → 답변 확인·수정 → 서버 저장 → 출발점·추천 이유 → 첫 활동 → 실제 기록 갱신 → 다음 추천.

진단 응답은 자기보고로만 보관한다. 직업·업무가 낯설거나 모르겠다면 guided, 업무를 알지만 결과물 경험이 충분하지 않다면 standard, 결과물 경험과 역량 인식이 있다면 challenge로 안내한다. 앞선 조건부터 적용한다. 이는 능력 등급이나 검증된 난이도 평가가 아니다.

- guided: 역할 설명과 단계별 힌트를 기본으로 펼친 직무체험.
- standard: 판단 중심 체험. 시작 안내 이후 힌트를 접어두고 필요할 때 열 수 있음.
- challenge: 개선안 비교·검증을 안내하는 프로젝트를 먼저 추천. 체험을 선택하면 비교 중심 안내를 제공.
- 전공·현직자 경험 응답은 후속 탐색 안내 문구에 반영. 검증된 학과 조사나 실제 만남 기록으로 인정하지 않음.

`backend/experience_graph/starting_point.py`에서 출발점을 계산한다. 기존 0~2 응답 기록도 그대로 해석하며 새로운 '모르겠음'은 3이다. 기존 DB 변경이나 가상 활동 추가는 없다. 새로고침 후 진단 화면과 경험지도에서 저장된 출발점을 볼 수 있다. 새 진단은 다음 추천과 신규 체험에 적용하며, 진행 중에 이미 확정된 안내와 선택 결과를 덮어쓰지 않는다.

## 사용자 확인 항목

테스트는 작성·실행하지 않았으며 아래 항목을 사용자가 확인한다.

1. 직업·업무를 모른다고 답한 학생은 안내형 체험을 추천받고 힌트가 기본으로 펼쳐지는지.
2. 업무 인식·결과물 경험·역량 인식이 있는 학생은 프로젝트를 추천받는지.
3. 같은 직업에서 응답을 바꾸면 출발점과 추천 이유가 달라지는지.
4. 마지막 확인 화면에서 수정 가능하고, 저장 실패 시 결과 완료 화면을 표시하지 않는지.
5. 진단 전후 활동 충족률이 그대로이고 자기보고가 별도 보관되는지.
6. 재접속 후 진단 화면·지도에서 출발점이 복원되고 다른 계정 기록과 분리되는지.
7. 추천한 체험 완료 후 프로젝트로 추천이 이어지는지, 중복 요청이 성취를 더 올리지 않는지.
8. 기존 체험의 진행과 조치 결과가 보존되고 신규 체험에 안내 수준이 반영되는지.

기존 진단 테스트의 예상 흐름은 질문 6 → 바로 저장에서 질문 6 → 답변 확인 → 저장으로 바꿔야 한다. 결과의 퍼센트 대신 출발점·추천 이유·활동 이동을 확인한다. API의 허용 응답 범위는 0~3이고 새로운 결과 필드를 확인한다.
