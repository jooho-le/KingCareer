# AI 연결 재검증 — 2026-09-13

후속 작업에서 Google Cloud의 실제 프로젝트 할당량을 조회하고 대체 모델을 비교했다. [모델별 한도 및 선정 결과](gemini-model-selection-2026-09-13.md)를 참고한다.

대상 코드: `a57edfe`. 로컬 `http://127.0.0.1:8000`과 배포 `https://kingcareer.vercel.app`에서 가상 계정을 사용했다. 기존 학생 기록과 키 원문을 출력하거나 수정하지 않았다. 테스트 계정은 양쪽 모두 삭제 완료했다. 서비스 코드·환경 설정·배포는 변경하지 않았다.

## 결론

실제 Gemini의 일시적 사용 불가와 무료 일일 한도 초과가 모두 관찰됐다. 애플리케이션은 서로 다른 오류를 같은 연결 실패로 변환한다. 또한 평가를 요청하기 전부터 미연결 상태를 저장하는 표시 문제가 있다. 앞선 분석처럼 재시도만 추가해서는 해결되지 않는다.

현재 로컬 환경에서 읽은 설정은 Gemini `gemini-3.8-flash`, `AI_MODE=ai`, 키 있음이다. 로컬·배포의 실행 API 모두 `mode=ai`를 반환했다. 배포 환경의 모델명·키·Google 프로젝트가 로컬과 동일한지는 이번 검사로 확인하지 않았다.

## 실제 외부 API 검사

로컬 설정을 사용해 실제 공급자 어댑터를 호출했다. 응답 본문이나 학생 텍스트 대신 HTTP 상태·종료 사유·토큰 수만 기록했다.

| 기능 | 공급자 응답 | 소요 시간 | 어댑터 결과 |
| --- | --- | --- | --- |
| 프로젝트 힌트 | 200 / STOP | 2.97초 | JSON 검증 성공, 전체 3.22초 |
| 프로젝트 평가 | 503 / UNAVAILABLE | 3.38초 | HTTPStatusError |
| 경험 회고 | 503 / UNAVAILABLE | 1.95초 | HTTPStatusError |
| 상황 응답 | 429 / RESOURCE_EXHAUSTED | 0.36초 | HTTPStatusError |

이어 한 번 더 확인한 공급자 오류 상세:

```json
{
  "status": 429,
  "provider_status": "RESOURCE_EXHAUSTED",
  "quotaMetric": "generativelanguage.googleapis.com/generate_content_free_tier_requests",
  "quotaId": "GenerateRequestsPerDayPerProjectPerModel-FreeTier",
  "quotaValue": "20",
  "quotaDimensions": {
    "location": "global",
    "model": "gemini-3.8-flash"
  }
}
```

이 20회는 검사에 사용한 프로젝트·모델의 응답에 명시된 값이다. 모든 Gemini 계정에 동일하게 적용되는 수치로 일반화하지 않는다. 실제 QA 호출도 사용량에 포함되므로 한도에 언제 처음 도달했는지, 과거 실패 중 몇 건이 한도 때문이었는지는 알 수 없다. 일일 한도 확인 후 이 키로 추가 생성 요청은 중단했다.

응답에 `retryDelay: 3s`도 있었지만, 위반 항목 자체가 일일 한도이므로 이 값만 보고 몇 초마다 반복 재시도해서는 안 된다. 한도는 API 키별이 아니라 프로젝트 기준이며 일일 한도는 태평양 시간 자정에 초기화된다. [Google 공식 사용량 제한 문서](https://ai.google.dev/gemini-api/docs/rate-limits)

## 실행 중인 앱 API 검사

각 환경에서 가입 → 가상 초안 저장 → 코치 요청 → 제출 → 평가 요청 → 회고 저장·생성 → 초안 재조회 → 계정 삭제를 수행했다.

| 항목 | 로컬 | 배포 |
| --- | --- | --- |
| 서버·DB 상태 | 200 | 200 |
| 실행 AI 모드 | ai | ai |
| 초안 저장 | 200 | 200 |
| 코치 힌트 | 503, 1.18초 | 503, 8.64초 |
| 프로젝트 제출 | 200 | 200 |
| 포트폴리오 평가 | 503, 1.11초 | 503, 8.60초 |
| 회고 생성 | 502, 0.97초 | 200 / ai, 8.63초 |
| 초안 글·그림 보존 | 확인 | 확인 |
| 가상 계정 삭제 | 200 | 200 |

배포에서도 실제 AI 회고가 성공했다. 배포의 두 503이 Google의 503인지, 429가 변환된 것인지, 다른 어댑터 오류인지는 공개 앱 응답만으로 확정할 수 없다. 서버·DB 상태가 정상이라는 사실은 AI 서비스가 정상이라는 뜻이 아니다.

## 앱 내부 오류 재현

실제 서비스와 분리된 임시 SQLite에서 오류 주입을 수행했다. 외부 모델은 호출하지 않았다.

1. 공급자 429, 공급자 503, 읽기 시간 초과, 미완료 출력, 잘못된 출력 모두 프로젝트 코치 API에서 동일한 503·동일 문구로 변환되는 것을 확인했다. `backend/main.py`의 포괄적 예외 처리가 원인이다. 회고 경로는 포괄적으로 502를 반환한다.
2. 가상 사용자 A의 코치 응답을 처리 중으로 유지하고 사용자 B가 요청했다. A는 200, B는 429였으며 공급자 호출은 한 번뿐이었다. 즉 B의 실패는 Gemini가 아닌 기능 전체 공용 잠금에서 발생했다.
3. 양쪽 실행 환경에서 AI 모드는 ai였지만 새 제출물의 `evaluationStatus`는 `not_connected`, 활동 `mode`는 `template`이었다. 아직 평가를 요청하지 않은 상태를 연결 상태와 혼용한다. `backend/main.py`에는 “AI 평가는 아직 연결되지 않았어요”라는 고정 안내도 있다.

코드 위치:

- `backend/inference.py:106`: HTTP 대기 30초, 자동 재시도 없음.
- `backend/inference.py:111`: 출력 한도 4096, STOP 및 JSON 검증.
- `backend/main.py:36`: 기능 단위 공용 코치 잠금.
- `backend/main.py:495`: 코치 예외를 동일한 503으로 변환.
- `backend/main.py:598`: 제출 시 미연결 고정 문구와 상태.
- `backend/main.py:655`: 평가 예외를 동일한 503으로 변환.
- `backend/reviews.py:184`: 회고 예외를 동일한 502로 변환.
- `src/api.ts:36`: 프론트엔드 응답 대기 45초.

이번 실제 실패는 대부분 수 초 만에 발생했다. 30초 시간 초과, 출력 토큰 부족, 형식 검증 실패를 이번 실제 장애 원인으로 확정할 근거는 없다. 오류 주입으로 처리 방식만 확인했다.

## 회귀 QA

- Playwright 6개 통과: `review-flow.spec.ts`, `studio-navigation.spec.ts`. AI는 모의 응답이며 화면 재시도·피드백 표시·기록 반영·다운로드를 검사했다.
- 임시 SQLite 서버 회귀 12개 통과: `backend_review_test.py`. 외부 AI 호출 없이 실패 후 데이터 보존, 동시 저장, 삭제, 중복 요청 등을 확인했다.
- 별도 오류 주입 6개 조건 재현: 오류 종류 5개와 다른 사용자 동시 코치 요청 1개.
- 실제 앱 AI 요청은 로컬 0/3, 배포 1/3 성공했다. 작은 표본이므로 장기 성공률로 해석하지 않는다.
- 프로덕션 코드는 바꾸지 않았으므로 이번에는 빌드를 재실행하지 않았다.

## 수정 우선순위

1. 원본 오류를 내부적으로 분류한다: 일일 한도, 분당 한도, 공급자 사용 불가, 시간 초과, 출력 검증 실패. 상태·오류 분류·소요 시간만 기록하고 키·학생 원문은 기록하지 않는다.
2. 일일 한도 초과는 자동 재시도를 중지한다. 초기화까지 대기하거나 실제 무료 한도·품질을 확인한 대체 모델을 선택한다. 유료 전환은 별도 결정이며 이번에 변경하지 않았다.
3. 503 및 일시적 분당 제한에만 제한적 지연 재시도를 적용한다. 전체 대기 시간을 서버·프론트와 함께 맞춘다. 무조건 재시도하면 일일 한도와 대기 문제가 악화될 수 있다.
4. 사용자별 중복 요청 제한과 서비스 전체 호출량 제어를 분리한다. 공용 잠금을 없애기만 하면 공급자 한도를 더 빨리 소모할 수 있다.
5. `not_requested`와 `not_configured`를 구분하고 “평가 전”을 “연결 안 됨”으로 안내하지 않는다.

증거 파일은 로컬 `.local/ai-qa-recheck.jsonl`, `.local/ai-quota-recheck.json`, `.local/ai-fault-probe.json`에 저장했다. 재실행용 스크립트도 같은 디렉터리에 있으며, 실제 생성 스크립트는 호출량을 소비한다.
