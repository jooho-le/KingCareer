# 리뷰 후 흐름·저장 개선

## 사용자 화면

- 프로젝트 관심도는 미선택으로 시작하고 그림·설명과 함께 자동 저장·복원합니다. 제출 전 선택을 확인합니다.
- 과제/내 설명/크랩 도움 탭에 좌우·Home·End 키 이동을 적용했습니다. 모바일 접기 버튼은 탭 목록 밖에 있습니다.
- 프로젝트 목록은 큰 소개 배너를 없애고 과제 선택과 진행 중 작업을 먼저 보여줍니다. 더 이상 사용하지 않는 이전 프로젝트 편집 흐름을 제거했습니다.
- 개발자는 연결된 화면 흐름도, 간호사는 인계 보드, 엔지니어는 전후 시험표, 연구원은 시료 비교표, 스마트팜은 온실 배치도에서 시작합니다. 첫 문장이 어려운 학생에게 직업별 말머리를 제공합니다.
- 포트폴리오는 최근 완료한 기록 종류에 맞춰 열리고, 프로젝트 카드에는 실제 설계도를 보여줍니다. 설계도·설명·회고·피드백을 함께 담은 HTML 문서를 내려받고 브라우저에서 인쇄/PDF 저장할 수 있습니다. 일반 다운로드는 활동 요약임을 표시합니다.
- 특정 결과물과 수료 화면에서 연 회고는 정확한 활동 ID를 유지합니다. 이미 남긴 회고 답을 재사용하고 빠진 질문만 보충합니다. 학생이 눌렀을 때만 AI 정리를 요청합니다.
- 홈의 대표 다음 활동은 진행 중 기록 → 학생이 고른 다음 활동 → 추천 순입니다. 재방문 화면은 안내 배너를 줄였습니다.
- 획득 배지에는 실제 행동에 근거한 획득 이유가 표시됩니다.

## 백엔드와 체험

- `005_project_progress.sql`은 기존 자료를 보존하면서 초안·수정 이력에 관심도 필드를 추가합니다. 변경 후 로컬 FastAPI를 재시작해야 합니다.
- 코치와 결과물 평가에 도형 종류·라벨·명시적 연결 정보가 전달됩니다. 그림의 시각적 완성도나 역량을 판정하지 않습니다.
- AI 평가·질문은 DB 잠금 밖에서 요청하고, 응답 저장 직전에 최신 상태를 다시 확인합니다. 삭제한 기록을 되살리지 않습니다.
- 수정 이력은 요약 목록과 선택한 원본 조회로 나눴습니다. 새 초안 저장의 중복 요청 응답도 이력을 참조해 그림을 중복 보관하지 않습니다. 기존 이력을 삭제하지 않습니다.
- 개발자 현장에는 인증 설정 문제와 로그인 처리 용량 문제의 두 사건을 준비했습니다. 완료 후 다시 체험하면 다른 사건으로 시작하며, 진행 중 세션은 원래 사건을 유지합니다.
- 재확인을 건너뛰면 확인하지 못한 사항이 남습니다. 조치만 했다고 자동으로 해결·검증 완료 처리하지 않습니다.
- 작은 화면·제한된 기기·움직임 줄이기 환경은 가벼운 3D 품질로 시작하며, 학생이 고른 품질을 브라우저에 기억합니다. 실제 기기 FPS에 따라 자동 조절하는 기능은 포함하지 않습니다.

## 검증 방법

전체 브라우저: `npm.cmd run test:e2e`. 화면 응답 기반 검사만 실행하려면 `npm.cmd run test:ui`, 실제 로컬 저장 검사는 `npm.cmd run test:api`를 사용합니다. 실제 저장 검사는 임시 계정 생성·삭제가 포함되고, 모델 호출은 대체합니다.

백엔드: `.venv\Scripts\python.exe tests/backend_review_test.py`, `.venv\Scripts\python.exe tests/test_simulation_review.py`. 임시 SQLite와 모의 AI로 검사합니다. 테스트는 사용자 기록과 모델 키를 출력하지 않습니다.

현행 서비스에 맞지 않던 구형 `tests/app.spec.ts`를 소개→선택한 체험→로그인, 모바일 프로젝트 선택, 이전 지도 링크의 프로필 연결 검사로 교체했습니다. 결과와 확인 범위는 [UI 검증 기록](ui-validation.md)을 참고합니다.
